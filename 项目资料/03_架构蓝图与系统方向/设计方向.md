# HealthPick 设计方向（系统方向）

> **版本：v1.20（最终交付版）**｜用途：系统能力边界与开发原则的总纲，架构蓝图为其细节展开
> 原则：先本地后联网；确定性优先于模型自觉；记忆贯穿；管道适配器热插拔，不重构底层。

## 一、定位
> **陪伴你吃饭、记得你一切饮食偏好的膳食顾问（饮食搭子）**

## 二、三大核心能力（做什么）

| # | 能力 | 要求 | 状态 |
|---|---|---|---|
| ① | **陪聊功能** | 像真人搭子：问候简短（≤30字）、共情温暖、闲聊不硬套知识库、情绪先接住 | ✅ 已落地（P5 陪伴 + 路由门控 + 问候简短化） |
| ② | **膳食顾问功能** | 用户提问**必须从知识库提取内容回答**：来源可溯、数值精确、禁忌排除、免责合规——**核心红线** | ✅ 已落地（自动化回归套件锁定） |
| ③ | **工具调用（联网）** | 实时信息获取：时令食材/天气/餐厅/最新资讯——饮食搭子"活着"的基础 | ⏸️ 规划中（当前版本默认关闭：联网查询引入外部依赖，与「断网可用」原则冲突；后续接入搜索 API 后按开关启用） |

## 三、不能失败的红线（不做什么也不能突破）

1. **本地库回答**：断网也必须能回答（A/B 知识库 + 本地规则引擎，零外部依赖）
2. **数值精确**：热量/蛋白/碳水只来自速查表工具计算，禁模型编造（165 千卡就是 165）
3. **疾病免责**：涉及疾病必须带"不构成医疗建议"（消息级 + 档案级延续）
4. **用药拒答**：任何用药问法一律拒答+免责（含英文药名/商品名/隐晦表述）
5. **禁忌排除**：已声明禁忌全链路剔除（正文/一餐/替换/点单/LLM 注入），正文零泄漏
6. **C 库隔离**：平台内容绝不混入营养回答（物理索引隔离 + current_query 闸门）

## 四、开发原则

1. **先本地后联网**：本地规则引擎永远可用，联网能力是增强不是依赖
2. **确定性优先**：能规则判定的不靠模型自觉（红线全规则硬逻辑）
3. **记忆贯穿**：过敏/目标/疾病/台账/坚持天数跨轮、跨端点生效（"记得你一切"）
4. **热插拔**：新能力走管道适配器（TTS/时间感知/点单/用户档案都是适配器接入），不重构核心

## 五、当前已落地 vs 愿景

**已落地**：首屏人格与场景卡、过敏追问（只问一次+持久化）、从问题到一餐（确定性生成）、一餐卡可视化、饮食台账记录/回查、情感陪伴四场景、TTS 语音、时间感知、成长记忆（streak/近7天）、点单决策、历史趋势、推荐解释、用户档案三模块、领域路由（膳食 vs 闲聊）、同义词召回、疾病引导语。

**规划中（v2.0）**：工具调用（联网搜索，默认关闭、按开关启用）；移动端适配（当前主做 PC 三栏版）。

**规划中（v3.0）**：检索与路由策略优化。
