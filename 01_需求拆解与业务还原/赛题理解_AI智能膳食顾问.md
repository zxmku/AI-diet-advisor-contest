# 赛题理解备忘 · AI智能膳食顾问（OPC接单吧第二届实战能力大赛·软件与智能体赛道）

> **版本：v1.20（最终交付版）**｜整理日期：2026-08-21
> 用途：把赛题原始要求拆解为可实施的业务需求，作为后续 SOP 与架构设计的输入。

## 一、比赛机制

- **限时 48 小时**（从赛题发布时刻起算，精确到分钟；超时系统自动关闭提交通道）。
- 评审分级 **C / B / A**，对应解锁 L1 / L2 / L3 测试单资格。
- 提交：代码仓库（GitHub/Gitee）或 Coze/Dify 分享链接 + 演示链接 + 部署说明 + 文档。

## 二、要做什么

为虚构平台「健康优选 HealthPick」做一个 **AI 智能膳食顾问**，7×24 服务三类人群：
减脂塑形 / 增肌强化 / 慢病调理（血糖血压偏高）。
四大能力：诉求识别 → 方案/食材推荐（1-2 个 + 1-2 句理由）→ 营养问答（带引用溯源）→ 可交互界面。

## 三、基础需求（底线：任何一项未完成 → 总分 ≤59 直接不及格）

1. **知识库问答与素材分类管理**：素材 A+B = 核心营养知识库（营养问答与推荐依据）；素材 C = 辅助平台资料（只答平台/会员/企业合作类问题，**不得参与膳食推荐**）。
2. **多轮对话与上下文记忆** + 会话管理。
3. **膳食方案/食材推荐**：推荐逻辑 + 推荐范围 + **禁忌识别**（糖尿病/尿酸高/过敏等→排除不适宜食材 + 提示咨询医师）。
4. **交付物与工程要求**：
   - 可运行系统（公网 URL / 微信二维码 / Coze·Dify 链接≥7天 / Docker 一键运行）——**纯本地脚本不算**；
   - 界面：整洁、有反馈、有错误提示（空输入/超长/异常各有指定提示语）；
   - 使用说明文档 ≥500 字（含技术选型与核心逻辑 ≥200 字）；
   - 系统架构说明 ≥300 字；
   - 基础功能测试记录 ≥5 组。

## 四、进阶需求（区分等级的关键，冲第一必须全拿）

1. 响应式 Web 界面 + 快捷操作；
2. **动态 LLM 调用**（禁止硬编码回复 + 模型来源标注）；
3. 用户系统 + 对话历史持久化 + 历史展示；
4. **公网部署 HTTPS**（或 15 分钟内可跑通的本地一键方案）+ .env.example 环境变量管理（Key 不得明文入库）。

## 五、红线（踩了直接死）

- ❌ 素材 C 与 A/B 混淆 = 编造（评委会专门测试会员价格是否被混进营养建议）；
- ❌ 疾病相关问题**必须**带免责声明「本建议仅供参考，不构成医疗建议，请咨询专业医师或注册营养师」，缺了即违规；
- ❌ 硬编码回复；白标商业产品；
- ❌ AI 辅助生成内容**必须在文档中标注**（哪些 AI 生成、哪些人工优化、理由），未标注或虚假标注 → 取消资格。

## 七、重要发现：评分细则缺失

试题 md 与 docx 内容完全一致，多个小节**只有标题没有正文**：
- 基础需求1 的「回答准确性」「引用溯源」「编造界定」无具体标准；
- 基础需求2 的「多轮对话示例」「会话管理」细则为空；
- 进阶需求各子项细则为空；
- **「评分标准」分值表全文未给出**（开头提到依据评分标准分 C/B/A，但标准本身不在这份文件里）。

→ 建设目标：基础需求全部满足、进阶需求全部落地、交付文档完整规范。

## 八、技术路线与实施策略

1. 技术路线：自研 Web 应用（Python 后端 + LLM API + 本地检索），不使用低代码平台配置化搭建——既满足「禁止白标」约束，也便于在架构说明中呈现真实工程实现；
2. 进阶需求四项全部落地：响应式 UI、动态 LLM 调用、用户系统与历史持久化、公网部署；
3. 合规与边界防线：素材分类隔离（素材 C 独立检索域）、免责声明强制注入、边界输入统一提示语；
4. 交付文档完整：使用说明、架构说明、功能测试记录、AI 辅助标注清单。
