## 三、支柱A 头条缺陷：多意图互吞（根因 + 修复）

### 现象（第三波压测 xfail 已记死）
句含「过敏澄清 + 平台价格 + 营养查表」三类子意图时（如"我对虾过敏，你们专业版会员多少钱？顺便说下鸡胸肉多少千卡"），**平台价格被吞**，仅回过敏澄清+营养+排除清单。

### 根因（main.py 编排链路）
- 数值问答走 `else` 分支（line 1700）→ `numeric_hit=True` 时直接 `return` 式组装（line 1710 设 reply/sources）；
- 平台处理块在 `if not numeric_hit and not numeric_miss:`（line 1748）内——**numeric_hit 为真时被整体跳过**，故平台价格段永不追加；
- 对照：`_is_meal_intent` 分支（line 1642）已用 `_platform_reply_prefix` 追加平台段（line 1669-1682），数值分支缺这一环 → 互吞只发生在「数值×平台」组合。

### 修复方案（手术式·小爆炸半径）
在 `numeric_hit` 块（line 1710 之后、sources 设定后）追加平台段，复用既有 `_platform_reply_prefix`（已做 C 库章节直选硬隔离）：
```python
# 支柱A：数值×平台同轮共存时，平台段不得被数值路径吞掉
plat_prefix, plat_chunk = _platform_reply_prefix(message)
if plat_prefix:
    reply = f"{plat_prefix}\n\n" + reply
    if plat_chunk:
        sources = sources + [{"source": plat_chunk.source, "chapter": plat_chunk.chapter,
                              "section": plat_chunk.section, "content": plat_chunk.content,
                              "score": plat_chunk.score}]
```
改动仅 1 处、约 8 行，不触及拒药/免责/数值/过敏逻辑。

### 红线自审（守门员逐条）
- 红线① C 库隔离：`_platform_reply_prefix` 走 C 库章节直选，平台文本作为独立前缀块，不与营养正文混合 → **不破**。
- 红线⑤ 数值精确：营养 reply 由 `format_reply(row)` 原样返回，未被改写/推算 → **不破**。
- 红线② 禁忌排除：过敏澄清/排除清单在 1926/1944 行照常追加，与本次改动无关 → **不破**。
- 红线③ 禁硬编码：平台文本取自 C 库内容，非硬编码 → **不破**。
- 红线④ Key：本改动不碰任何密钥 → **不破**。
- 无 AI 味：纯规则拼接，未引入 LLM 生成 → **不破**。
