# 使用说明 · AI 智能膳食顾问（HealthPick）
> **版本：v1.20（最终交付版）**

> 本文档面向评审与使用者，说明系统如何访问、如何使用、能力边界与合规约定。全文不含内部工程黑话。

## 一、系统是什么

AI 智能膳食顾问是一个面向「减脂塑形 / 增肌强化 / 慢病调理（控糖）」三类人群的饮食助手。用户输入食材、热量或方案类问题，系统基于《中国居民膳食指南》与结构化知识库（素材 A 营养基础、素材 B 三套方案、素材 C 平台服务隔离）返回**带来源标注**的膳食参考；接入大模型后为完整 AI 顾问模式（在检索结果之上生成更自然、更有陪伴感的回答），大模型不可用时自动降级本地规则兜底，基础功能完整可用。

产品围绕「从问题到一餐」展开：不止回答问题，更能直接帮用户**搭出完整一餐**（食材 + 克数 + 做法 + 热量 + 替换 + 采购清单），并记住用户的偏好、禁忌与坚持情况——**聊起来、记得我、陪你坚持**。

## 二、如何访问（云端部署，免安装）

系统已部署至云端服务器，提供公网 HTTPS 访问，**考官与使用者无需在本地安装任何环境**，打开链接即可体验完整功能：

> **线上体验地址：https://&lt;你的公网部署地址&gt;**

服务端以 FastAPI 单端口托管前后端与知识库，公网入口统一转发至该服务；密钥由服务端配置，使用者无需关心。

## 三、默认即完整 AI 模式

系统默认运行完整 AI 顾问模式：大模型在检索到的知识块之上组织自然语言回答，先共情后建议、口语化、场景化，闲聊与陪伴更自然。若大模型服务暂时不可用，系统自动降级为本地规则模式（BM25 检索 + 合规层 + 确定性一餐生成），基础功能仍完整可用，绝不白屏——两种模式下数值与医疗结论均不编造。

## 四、它能为你做什么

1. **场景入口与一键方案**：首屏展示顾问人设欢迎语与四张场景卡（减脂塑形 / 增肌强化 / 控糖调理 / 今日食谱），点击即渲染真实方案卡；已有历史会话时自动恢复对话。
2. **数值精确问答（防幻觉）**：问「鸡胸肉多少千卡」「鸡蛋多少蛋白质」等，返回权威速查表的精确值并标注来源；表中未收录的食材诚实告知，绝不臆测。
3. **三套方案推荐**：减脂（轻盈减脂方案）、增肌（力量增肌方案）、控糖（稳糖调理方案），返回热量区间、代表食材、推荐理由与来源。
4. **快捷操作**：顶部一键获取减脂 / 增肌 / 控糖方案或今日食谱。
5. **多轮对话与历史面板**：同一会话内上下文会被记忆，历史消息落库、刷新不丢；前端历史面板可查看并切换历史会话。
6. **过敏追问与记忆**：首次声明过敏/禁忌（如「我对海鲜过敏」）时，以真人顾问口吻追问细分类型（只问一次），并把禁忌持久化进会话画像——之后每一轮都记得、自动排除；消息隐含人群目标（如「血糖偏高」「想减脂」）会自动更新目标画像。
7. **一餐生成**：直接说「今晚减脂餐」「给我做晚餐」「今天吃什么」→ 得到**完整一餐**：主蛋白 + 主食碳水 + 蔬菜 + 好脂肪（含克数）、总热量、营养三条、2-3 步做法、同族替换建议；热量与营养素全部来自营养速查表真实值 × 份量，表外食材标注「约计」不编造；无目标时先追问「想减脂、增肌还是控糖？」。
8. **一餐卡可视化**：一餐以卡片呈现——标题、食材清单（分类标签 + 克数 + 热量）、总热量大数字、营养三条、做法步骤、替换建议、来源小字。
9. **采购清单**：一餐卡内直接展示「采购清单」——由这餐的食材与克数一键派生，照着买即可。
10. **饮食台账记录与回查**：说「早餐吃了两个鸡蛋和一杯牛奶」→ 记入饮食台账并按速查表估算热量；问「我最近吃了什么」→ 回查最近记录。
11. **情感陪伴**：说「一个人吃饭好孤单」「没胃口」「加班好累」等 → 先共情再轻建议，数值同样来自速查表（零编造）。
12. **语音朗读（可选）**：每条助手回答右侧有小喇叭按钮，点击即用拟真人神经语音朗读。语音为可选组件，不可用时文字回答不受影响。
13. **时间感知**：按当前时段（早/午/晚/夜宵）自动调整问候语与建议焦点。
14. **成长记忆（健康状态）**：基于饮食台账记住坚持与近况——首屏展示「连续坚持 N 天 / 今日已记 N 餐 / 近 7 天共记录 N 餐」，欢迎语结合坚持天数主动问候。
15. **点单决策（站在餐厅前的 30 秒）**：说「我在麦当劳准备点餐」「肯德基」「便利店」「吉野家」「兰州拉面」「中餐外卖」「火锅」等，系统按你的目标（减脂 / 增肌 / 调理）直接给出可执行点单建议（选什么 + 为什么 + 怎么改）；点单建议为行为决策，只给定性指引，具体以餐厅实际出品为准；已声明禁忌自动过滤。
16. **为什么适合你（推荐解释）**：推荐方案卡内说明——基于你的目标解释方案的热量与蛋白定位、食材组合如何匹配你的阶段需求，不引入素材外数值。
17. **成本闸门**：大模型模式下的预算、回复缓存、会话限速与成本记账，保证费用可控、可观测。
18. **用药拒答与免责**：涉及疾病/症状/用药的问题强制附加医疗免责；含用药咨询一律拒答、只给膳食参考（判定优先级最高）。
19. **禁忌排除**：对话中声明过敏/禁忌后，回答正文、推荐食材、一餐生成与点单建议均自动剔除对应禁忌食材，并明示排除清单。
20. **用户档案（"它记得我"）**：顶部点击头像打开档案抽屉——「我是谁」展示昵称 / 使用天数 / 当前目标；「它记得我」汇总过敏与不耐受、慢病管理、已帮你排除的食材、近 7 天记录与最近台账；「下一步建议」给出当前最该做的事，点击即可执行；支持**禁忌编辑**——按系统已知类别勾选，保存后立即生效并影响后续所有回答。
21. **领域路由（两种模式）**：系统先判断这是「膳食顾问需求」还是「闲聊/非膳食」——营养、食材、热量、方案、禁忌类问题走知识库检索回答；打招呼、问身份、聊生活等自然回应，绝不硬套膳食内容。
22. **同义词查询扩展**：支持口语与别名问法——"鸡脯肉多少千卡"自动归一为"鸡胸肉"命中权威表、"减重/减肥"等同"减脂"、"西红柿"等同"番茄"；口语问法不再因措辞差异漏判。
23. **疾病画像引导语**：当会话已声明慢病（高血压/糖尿病/痛风等），回答自动带"结合您的控盐/控糖/低嘌呤需求"的差异化引导，且跨轮延续。

## 五、能力边界与合规约定（红线）

1. **C 库隔离**：营养问答绝不混入平台价格、会员、企业方案等素材 C 内容；仅在明确问到平台服务时才检索 C 库。
2. **医疗免责**：凡涉及疾病、症状、用药的问题，系统强制附加「本建议仅供参考，不构成医疗建议，请咨询专业医师或注册营养师」。
3. **用药拒答**：含用药咨询一律不提供用药建议，且优先级高于其它意图。
4. **数值防幻觉**：数值（热量/蛋白/碳水/克数）必须来自知识库权威表（速查表 × 份量），禁止模型推理编造；表外食材诚实告知"暂未收录"。
5. **禁忌排除**：对话中声明过敏/禁忌后，回答正文、推荐食材、一餐生成与点单建议均自动剔除对应禁忌食材。
6. **零真实密钥泄露**：代码与仓库不含任何真实 API Key，密钥仅经服务端环境变量注入。

## 六、常见问题

- **为什么有的回答是检索原文、有的更口语？** 默认即大模型在检索结果上的自然语言组织；大模型不可用时自动降级本地规则（检索原文直出 + 来源标注），两者均不编造数值与医疗结论。
- **一餐的热量怎么来的？** 每个食材的热量/营养素取自营养速查表真实值，按份量计算后求和；速查表未收录的食材不编造精确值，标注「约计」并说明。
- **点单建议为什么没有具体热量数字？** 点单决策是「站在餐厅/外卖前 30 秒」的行为建议，只告诉你选什么、怎么改，避免给出未经权威核实的精确数字；具体以餐厅实际出品为准。
- **我怎么知道它记得我的过敏？** 首次声明过敏会收到追问与「已记录」确认；之后任意一轮，回复正文、推荐、一餐与点单建议都会自动剔除禁忌食材，并在尾部列出排除清单。也可以点顶部头像打开「用户档案」抽屉查看全部记忆，随时勾选管理禁忌。
- **语音按钮提示「暂不可用」？** 语音朗读为可选组件，不可用时优雅降级提示，不影响文字回答。
- **数据存哪里？** 会话、历史与饮食台账在服务端持久化，刷新不丢；跨用户隔离，归属校验防串号。
