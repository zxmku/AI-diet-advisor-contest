# 支柱C · 考核评分（饮食评估打分）方案

> 状态：**已修订**（初稿审查发现 1 处字段名硬伤 + 2 处实现注意，已修正）。待用户点头后实施。
> 定位：基于现有 `DietLog` 台账 + `NUTRITION_TABLE` 速查表，给用户「当天饮食」打一个结构化分数 + 分项 + 建议。
> 设计原则：**纯规则路径、数据驱动、零 LLM 自由发挥** —— 数值严格来自素材表真实值，文案用温暖真人语气模板，不赌 BM25、不赌模型。

## 一、缺口确认（已实证）
- `backend/app/` 全仓 grep `score/evaluate/评分/打分/评估` → 仅 `retrieval.score` 检索分与 `meta.model` 标识，**无任何饮食评分能力**。
- 现有组件可复用（不重复造轮子，已实跑验证）：
  - `main.py:662 _estimate_diet_kcal(message)` → `(total_kcal, items=[{food,grams,kcal}])`，全部 = 速查表真实值 × 份量（红线⑤合规）。
  - `main.py:783 _handle_diet_query` → 已从 `DietLog` 按 `user_id` 取最近 5 条（仅加"按天过滤"即可）。
  - `NUTRITION_TABLE[row]`（实测 31 行）含真实字段：`kcal / protein / fat / cholesterol`（非 `protein_g`！见第十节硬伤）。
  - 份量逻辑：消息带克数按用户份量，否则按常见份量 100g 估算（现有规则，约计标注）。

## 二、能力定义
触发后：
1. 取该 `user_id` **当日** DietLog 记录（按 `created_at` 过滤当天，≥1 条；无则引导先记账）。
2. 逐条调 `_estimate_diet_kcal` 汇总全天 `total_kcal` 与食物明细；蛋白 = Σ(`row["protein"]` × grams/100)（row 用归一化 key 查表，见第十节）。
3. 对照**推荐基准**（数据驱动，非编造）算三维分，合成 0–100 总分。
4. 输出：总分 + 三维分条 + 温暖建议（模板化）+ 免责（若调理/慢病/含疾病词）。

## 四、评分维度与公式（数值来源全部可溯）
| 维度 | 权重 | 计算 | 数值来源（已实锤合规） |
|---|---|---|---|
| 热量合理性 | 40% | 全天总热量落 `[1200, 2200]` 千卡 → 满分；超出按线性扣分 | 食物 `kcal` 来自速查表真实值 × 份量 |
| 蛋白质达标 | 35% | 实际蛋白 ÷ 目标蛋白（目标 = 体重kg × **1.2–1.6 g/kg**） | 食物 `protein` 字段来自表真实值；系数来自**素材A:65「每公斤体重1.2-1.6克蛋白质，保护肌肉」**及**素材B:17「体重(kg)×1.2克/日」**——红线⑤合规，非自编 |
| 餐次均衡 | 25% | 早/午/晚覆盖数 ÷ 3（加餐计入就近正餐） | DietLog.meal_tag |

- **缺数据降级**：无体重 → 蛋白维度标「需提供体重以精确评估」，用通用提示语；无当日记录 → 引导「先告诉我今天吃了什么，我帮你记」。
- **约计标注**：份量按 100g 常见份量估算时，回复明示「按常见份量估算，仅供参考」。

## 十、实现注意（审查实证发现，必读）
1. 🔴 **字段名硬伤（已修正）**：营养表蛋白字段实测为 `protein`（鸡胸肉字段键 `['key','display_name','source_chapter','source_section','kcal','protein','fat','cholesterol','audience']`），**不是** `protein_g`。取数用 `row["protein"]`。
2. 🟡 **口语食物解析局限（继承基座，不扩大修复）**：`_estimate_diet_kcal` 对"水煮蛋"类口语（表 key 为"鸡蛋"）会漏识别——实测「早餐吃了一个水煮蛋、一杯无糖豆浆和一根玉米」仅解析出豆浆+玉米（蛋漏）。评分将基于**已识别食物**，未识别的不计入，且回复标注「部分食材未能精确识别，评分仅供参考」（契合红线⑤约计）。不顺便修 `_estimate`（属独立议题）。
3. 🟡 **蛋白取数方式**：不能拿 `_estimate` 返回的 `display_name`（如"豆浆（无糖）"）直接查 `NUTRITION_TABLE`（display_name≠key，且谷薯类无 `protein` 字段→None）。评分函数应**自己用 nutrition_lookup 的归一化 lookup 取 protein**，对 `None` 跳过（不计入蛋白维度）。
