## 一、项目理解与评分标准映射

### 1.1 业务场景
健康优选（HealthPick）面向 25–45 岁都市白领，推出 7×24 小时 AI 膳食顾问，替代传统人工营养咨询。系统需：识别用户健康诉求、推荐膳食方案/食材、回答营养问题、提供基础可交互体验。

### 1.2 三大目标人群
| 人群 | 诉求 | 对应方案（素材 B） |
|---|---|---|
| 减脂塑形 | 科学减重、控热量、三餐搭配 | 轻盈减脂方案（1200–1800 千卡/日） |
| 增肌强化 | 增肌、蛋白需求、训练前后饮食 | 力量增肌方案（训练日 2500–3000 千卡） |
| 慢病调理 | 低 GI、控盐控糖、饮食禁忌 | 稳糖调理方案（控糖 321 餐盘） |

### 1.3 产品定位（产品级定位，团长定调）
> 「比赛规则的硬性需求只是合格分数线；我们想拿第一，就要产品级定位——把自己当成真正的开发团队，围绕产品打磨、开发和迭代。」

**一句话产品定义**：HealthPick 是一个「**记得你的 AI 膳食陪伴顾问**」——不是查资料的问答机器人，而是记住你是谁（减脂/增肌/调理目标、食物禁忌、过敏史）、记得你吃了什么（饮食台账）、在你站在餐厅/外卖/便利店前最后一刻给出可执行点单决策的陪伴型营养助手。

**产品三模块**（引导 / 记忆 / 陪伴）：
1. **引导（Guidance）**：首屏人格欢迎语 + 四张场景入口卡（减脂/增肌/控糖/今日食谱）→ 一键调 `/api/quick` 渲染真实方案卡；疾病画像用户带差异化引导语（糖尿病→「结合您的控糖需求」、痛风→「结合您的低嘌呤需求」、高血压→「结合您的控盐需求」，跨轮延续）。
2. **记忆（Memory）**：过敏只问一次、问完持久化，之后每轮自动排除禁忌；目标画像动态更新且不被纯请求语义覆盖；饮食台账「记得你吃了什么」；成长记忆（连续坚持天数 streak、近 7 天趋势）——「它记得我」可见化（用户档案抽屉 👤）。
3. **陪伴（Companion）**：「一个人吃饭好孤独」先共情再给轻建议；🔊 语音朗读（edge-tts 拟真人神经语音）；时间感知问候（早/午/晚/夜宵分段建议焦点）；点单决策（麦当劳/肯德基/便利店等 7 场景 × 3 目标）。

**凭什么拿第一**：
- **红线密实**：用药硬拦截（拒药 + 免责）、疾病必带免责、禁忌全链路剔除（正文剔除 + 同族替换过滤 + 引号保护）、数值必须工具计算（速查表精确值，禁模型编造）、C 库物理隔离——全部规则硬逻辑，零幻觉、零模型自觉，评测诱导问法（英文药名/商品名/症状式过敏/多轮诱导）均有自动化红线用例锁定。
- **产品感**：从「能回答问题」升级到「引导 → 记忆 → 陪伴」完整产品闭环，有真实 UI 细节（一餐卡、历史面板、场景卡、语音、档案抽屉、状态 chip）。
- **记忆贯穿**：禁忌/目标/台账/坚持天数贯穿多轮与多端点，画像只读聚合 + 三守卫（白名单/引导语/不进 LLM）。
- **语音陪伴**：TTS 拟真人语音朗读回复，零 Key 零成本，缺依赖优雅 503 降级不崩。

## 二、总体架构

- **架构模式**：分层架构 + 检索增强生成（RAG）+ 对话驱动 + 管道适配器（时间感知/TTS/成长记忆/点单决策热插拔）。表现层 / 应用层（对话编排、推荐、合规）/ 知识层（双层隔离）/ 模型层 / 数据层 / 可靠性层（成本闸门）清晰解耦。
- **通信模式**：前端 ↔ 后端 REST（HTTP/JSON，同源静态托管免 CORS）；后端 ↔ LLM HTTPS API 调用（受 M17 闸门包裹）。
- **数据模式**：会话状态 + 检索增强为主；知识库只读检索源，用户/会话/台账为可写持久态。
- **部署模式**：Docker Compose 一键（零配置）+ 本地 launch_8137.bat 双轨；容器 8137 在线（真 AI）。

### 2.2 意图优先级链（实测锁定，main.py chat()）
```
输入校验(validate_message)
  → 禁忌识别三路合并（请求 allergies + 对话触发 + 会话已声明）
  → 用药硬拦截 is_medication_query ──命中──► 拒药 + 免责（绝不被台账/陪伴/一餐/决策劫持）
  → 数值精确问答 is_numeric_lookup_query ──命中──► 速查表精确值（表外诚实 miss，不回退 BM25）
  → 一餐意图 _is_meal_intent ──命中──► _build_meal 确定性出餐（无目标先追问）
  → 点单决策 decision_tool.resolve ──命中──► 7 场景点单建议（行为决策，不引精确数值）
  → P5 台账/陪伴 _try_p5_intent ──命中──► 记录/查询/陪伴（先共情）
  → 检索/LLM：is_dietary_domain 领域门控（膳食→RAG；非膳食→闲聊三分类）
```
> 注：P5 分支在 main.py 中先于检索判定，但**受 `is_med_query` 前置闸门保护**（V01 修复）——「我吃了布洛芬怎么办」走拒药而非记台账。

### 2.3 数据流（输入 → 路由 → 合规 → 检索/生成 → 画像 → 响应）
```
用户消息
  │
  ▼
validate_message（空/超长边界）→ 禁忌识别（compliance.detect_allergies）
  │
  ▼
意图链路由（用药 → 数值 → 一餐 → 决策 → P5 → 检索/闲聊）
  │                     │
  │              [检索] retrieve(ctx_query, top_k=4, current_query=message)
  │                     │       BM25(A+B) + 同义词扩展；C 库仅平台闸门命中才检索
  │                     ▼
  │              LLM 合成（llm.synthesize：grounding + excluded_foods 注入 + state_context + 时间感知）
  │                     │
  ▼                     ▼
合规收尾：正文禁忌剔除（R3，引号保护）+ 免责注入 + 排除提示
  │
  ▼
画像持久化（_update_session_profile：goal_tag/allergies 白名单守卫）
  │
  ▼

```

## 四、服务/模块分解（高层）

1. **对话服务（M4/M5）**：意图链编排（用药→数值→一餐→决策→P5→检索/闲聊）、多轮上下文、画像持久化。
2. **推荐服务（M8）**：人群标签→方案+食材+理由（why）；快捷操作（/api/quick 四类）。
3. **知识检索（M6/M7）**：核心库 A+B 与辅助库 C 硬隔离，按平台闸门路由。
4. **数值问答（M9）**：营养速查表确定性查询 + 表外诚实 miss。
5. **合规服务（M10/M11）**：禁忌识别（13 类 + 症状正则）+ 免责/拒药强制注入 + 引导语。
6. **用户服务（M12）**：身份识别、对话历史、成长记忆、用户档案。
7. **可靠性服务（M17）**：成本闸门包裹所有外部调用。

## 五、知识库分层设计（落地状态）

### 5.1 双层隔离架构（已落地）
- **核心营养知识库（A+B）**：素材 A 16 块 + 素材 B 14 块，用于所有营养膳食问答、食材推荐、方案推荐依据。
- **辅助平台资料（C）**：素材 C 15 块，独立索引，**仅当 query 显式命中平台意图（PLATFORM_HINTS：会员/价格/多少钱/费用/企业/SaaS/API/案例/白皮书/平台/套餐/订阅/定价）时才检索**；营养问答路径永不查询 C。
- 实测证据：多轮诱导（`会员多少钱一个月` → 闲聊 2 轮 → `给我推荐减脂餐`）后营养回答 sources 全部 A/B，零 C 混入。

### 5.2 核心库（A+B）结构
- A：营养素基础（1.x）、秋季膳食搭配原则（2.x）、常见食材营养数据速查表（3.1–3.4，31 行）、特殊人群饮食注意事项、膳食安全与禁忌。
- B：方案体系概述、轻盈减脂/力量增肌/稳糖调理三套方案（目标/7 日循环食谱/替换指南）、方案使用指南。
- 分块带元数据 `{source, chapter, section, content}`，支持引用溯源。

### 5.3 辅助库（C）隔离墙与路由
- 独立 BM25 索引（bm25_c），仅 `PLATFORM_HINTS` 命中才检索；且**闸门只看本轮 current_query**（retrieve 的 current_query 参数），多轮拼接历史中的平台词不触发 C——杜绝「上一轮会员价 → 本轮营养问」越红线。
- 实测证据：R1-1/R1-2/R1-3 三组诱导用例全部通过。

### 5.4 引用溯源机制
- 回答末尾自动追加来源：`sources[].source/chapter/section`，前端「📚 来源：」小字展示；一餐卡/方案卡均带来源标注（source A/B，无 C）。
- 数值问答溯源到具体章节（如「【第三章常见食材营养数据速查表 · 3.1 肉类与海鲜】」）。

## 八、安全与合规设计（已落地）

### 8.1 健康免责声明强制注入
- 标准文案（逐字）：`本建议仅供参考，不构成医疗建议，请咨询专业医师或注册营养师`。
- 命中疾病/症状关键词（compliance._DISEASE_KEYWORDS，含审计 V05 扩充：糖尿病/血糖/痛风/肾病/孕期/高血压/甲亢/脂肪肝/甲减/血脂高/血压偏高/尿酸偏高/贫血/肿瘤/癌症/失眠/抑郁/焦虑等）即强制注入，规则硬逻辑不依赖 LLM 自觉。
- 免责跨轮延续：_session_has_disease 扫会话历史 + _session_profile_has_disease 读档案疾病，次轮无病名仍带免责。

### 8.2 用药硬拦截
- is_medication_query（_MEDICATION_KEYWORDS，含裸「药」+ 白名单豁免 山药/药膳/药食同源 + 审计 V03 扩充：GLP-1 诺和泰/诺和力/度拉糖肽/ozempic/wegovy/rybelsus、处方药 优甲乐/立普妥/络活喜/倍他乐克/代文、英文 OTC advil/tylenol/naproxen/diclofenac/codeine、错别字 止疼片）→ 一律拒答「不提供用药建议，请遵医嘱」+ 免责。
- 优先级最高：用药拦截先于 P5 台账/陪伴（V01）、先于一餐（R2）、先于点单决策（O4-7）、先于检索（司美格鲁肽命中减脂块仍标 medication_refuse）。

### 8.3 API Key 与密钥管理
- 敏感配置仅存环境变量；仓库只留 .env.example（全字段可选，零配置可跑）；真实 Key 经 deploy/.env（gitignore）注入。
- 日志脱敏层（secret_redaction.py：sk-/AKIA/ghp_/Bearer/api_key 正则），异常日志与响应不回显密钥；`/health` 仅回显 `llm_key_set` 布尔。

### 8.4 输入校验与限流
- 空输入 →「请输入您的问题」；超长（>500 字）→「输入内容过长，请精简后重试」；异常 →「服务繁忙，请稍后重试」——三套指定提示语全局统一常量。
- 限流按 session/用户级（X-Session-Id → X-User-Id → IP），桶容量封顶 4096，超限 429 + 统一响应格式。

### 8.5 引导语（M11 双模板的延伸）
- 疾病画像用户差异化引导：`结合您的控糖需求 / 低嘌呤需求 / 控盐需求`（_DISEASE_LABELS 映射），跨轮延续；普通用户不误加「结合您的」（测试锁定）。

## 九、异常处理与边界条件（已落地 + 审计加固）

| 边界 | 处理 |
|---|---|
| 空输入 | 前端禁用发送 + 后端「请输入您的问题」（HTTP 200 统一响应） |
| 超长输入 | 前端 maxlength 500 + 后端「输入内容过长，请精简后重试」 |
| 特殊符号/emoji/纯英文 | 非膳食领域走闲聊三分类，礼貌引导回营养话题 |
| 无关输入 | is_dietary_domain 领域门控：「大龙虾吃什么/世界首富是谁/1加1等于几」走闲聊，绝不硬套膳食知识块 |
| 系统异常 | 全局异常兜底 →「服务繁忙，请稍后重试」+ 日志脱敏 |
| LLM 超时/失败 | 无缝降级 local-rules（检索直出 / 本地模板），degraded=true 标注 |
| LLM 无 Key | is_enabled()=False，全量规则路径，零配置可演示 |
| 数值防幻觉 | 命中速查表 → 精确值直出；表外 → 诚实「表中暂未收录」，绝不回退 BM25 模糊编造 |
| 点单决策数值纪律 | 行为决策只给定性建议（去酱/去皮/高蛋白），不出现「数字+千卡」（测试断言） |
| 成本闸门触发 | 预算/缓存/限速三层，命中即降级，绝不阻塞主流程 |
| 并发写 | SQLite WAL + busy_timeout 5s；9900 请求压测 0 崩溃 |
| 语音缺失 | edge-tts 不可用 → /api/tts 503 → 前端 toast 降级不崩 |

## 十一、产品化迭代与质量加固（P1–P5 → 整夜迭代 → 审计修复 → 用户档案）

> 产品化迭代轨迹（每轮均有 pytest 用例 + 30_测试记录 43 项证据，HEAD 推进至 `20b463a`）。

### 11.1 P1 首屏人格与场景入口卡（HEAD `adb78ba`）
欢迎语（小优）+ 四张场景卡（减脂/增肌/控糖/今日食谱），点击调 /api/quick 渲染真实方案卡；有历史会话自动恢复，不重复欢迎语。

### 11.2 P2 过敏追问与记忆（`060c338 / 2304a4c / 0b20dbc`）
首次声明过敏 → 顾问口吻追问细分类型（海鲜/坚果/乳糖/麸质四套话术，只问一次）；过敏/目标画像持久化进会话，跨轮自动排除禁忌；目标动态更新（血糖偏高→调理）且纯请求语义不覆盖（DEFECT-B）；追问原文不被 R3 剔除循环破坏（DEFECT-A）。

### 11.3 P3 从问题到一餐（`4e00edf / 5c68ef2`）
「今晚减脂餐」「给我做晚餐」→ 确定性一餐生成器 _build_meal：主蛋白/主食碳水/蔬菜/好脂肪四槽位 + 克数 + 总热量 + 营养素 + 做法 + 同族替换 + 采购清单；热量 = 速查表值 × 份量（可核对，663.5 千卡示例）；无目标先追问（meal_goal_ask）；R1 数值优先 / R2 用药优先回归锁定。

### 11.4 P4 一餐卡可视化（`4e00edf` 随 P3）
一餐以卡片呈现：总热量大数字、营养素三条（蛋白/碳水/脂肪）、食材清单、做法、替换建议、来源、🛒 采购清单；表外食材（橄榄油）标注「热量约计」不编造。

### 11.5 P5 台账与陪伴（`92ce0cf / b739a06`）
「帮我记一下：早餐吃了两个鸡蛋和一杯牛奶」→ DietLog 落库 + 速查表热量估算确认；「我最近吃了什么」→ 最近 5 条台账汇总；「一个人吃饭好孤独」→ 先共情再轻建议（本地模板 / LLM 双链路，模型标注诚实）。

### 11.6 整夜迭代（管道适配器四件套 + 成长记忆，`17d0d63 → af36c70`，45 用例）

- **时间感知**（time_context）：早/午/晚/夜宵四时段问候与建议焦点，LLM 系统提示注入「当前时段」。
- **成长记忆**（health_state + /api/state）：streak（连续坚持，时区本地化）、today_summary、week_trend、greeting；state_context 注入 LLM。

## 十五、架构师裁决回顾（v2 → v3 落地印证）

- **"零成本不接外部 API" vs "接 DeepSeek 动态 LLM"**：裁决保留真 LLM 调用 + 成本闸门/本地兜底——已落地印证：容器实测 llm_key_set=true、meta.model=deepseek-chat；无 Key 时纯规则降级可演示。
- **React vs 原生零构建**：裁决"冲 A 体现能力但零配置优先"——落地选择**原生 HTML/JS 单页**（更稳、评委任意目录可跑），以产品细节（一餐卡/语音/档案抽屉/场景卡）体现能力，不依赖构建链。
- **"先保底纯本地" vs "先接 API 冲质量"**：dry-run 三阶段落地为实际执行轨迹，阶段 1 纯本地保底后逐级冲级，最终 122 用例全绿、容器 8137 真 AI 在线。
