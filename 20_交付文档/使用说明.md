# 使用说明 · AI 智能膳食顾问（HealthPick）

> 本文档面向评审与使用者，说明系统如何启动、如何使用、能力边界与合规约定。全文不含内部工程黑话。

## 一、系统是什么

AI 智能膳食顾问是一个面向「减脂塑形 / 增肌强化 / 慢病调理（控糖）」三类人群的饮食助手。用户输入食材、热量或方案类问题，系统基于《中国居民膳食指南》与本地结构化知识库（素材 A 营养基础、素材 B 三套方案、素材 C 平台服务隔离）返回**带来源标注**的膳食参考；接入真实大模型后可在检索结果之上生成更自然的回答，未接入时自动降级为本地规则模式，所有功能完整可用。

产品围绕「从问题到一餐」展开：不止回答问题，更能直接帮用户**搭出完整一餐**（食材 + 克数 + 做法 + 热量 + 替换 + 采购清单），并记住用户的偏好、禁忌与坚持情况——**聊起来、记得我、陪你坚持**。

## 二、启动方式（零外部依赖，离线可跑）

**方式 A：一键启动（推荐评审验证，Windows）**
1. 确保本机已安装 **Python 3.10 / 3.11 / 3.12**（一次即可，属运行环境；官网 https://www.python.org/downloads ，安装时勾选 *Add to PATH*）。
2. 双击项目根目录 **`一键启动.bat`** → 脚本自动读取 `deploy/.env` 密钥、用**仓库自带的离线依赖包**（`deploy/wheels/`）安装运行环境（**无需联网**）、启动服务、浏览器自动打开。
3. 浏览器访问 `http://127.0.0.1:8137/`（API 与前端同端口，打开即用）。
4. 配置密钥（要接入真 AI 时）：用记事本打开 `deploy/.env`，填入 `DEEPSEEK_API_KEY=你的密钥`，保存后重新双击即生效。
5. 零配置兜底：不填密钥也能用全部核心功能（本地规则模式，仅无 AI 润色）。手动运行时，在 `backend/` 下执行 `pip install --no-index --find-links ../deploy/wheels -r requirements.txt` 安装离线依赖，再 `python -m uvicorn app.main:app --host 127.0.0.1 --port 8137`。

**方式 B：Docker 容器部署（可选进阶）**
1. 需本机已装 Docker，且首次需联网拉取镜像：`cd deploy && docker compose up -d`。
2. 浏览器访问 `http://localhost:8137`。

**补充说明（环境检测 / 换电脑 / 密钥纪律）**
- `一键启动.bat` 自动查找本机 Python 3.10/3.11/3.12；找到后用**仓库自带的离线依赖包**安装（不访问外网）；若未找到 Python，会明确提示去 python.org 安装，不会擅自联网下载。
- 换电脑可用：所有路径由脚本所在目录自动推导，**零硬编码物理路径**——把整个项目文件夹拷到任意电脑，双击即用。
- 密钥纪律：密钥写入 `deploy/.env`（已 gitignore，不进仓库）。
- **核心零外部依赖**：运行所需全部 Python 包已随仓库打包于 `deploy/wheels/`，启动与核心问答**全程不访问外网**（语音朗读除外，见下文）。

## 三、接入真实 AI（可选，升级不替换）

- 在 `deploy/.env` 中填写 `DEEPSEEK_API_KEY=你的密钥` 后重启服务（重新双击"一键启动"），系统即升级为 DeepSeek 动态生成模式：模型在检索到的知识块之上组织自然语言回答，闲聊与陪伴也更自然。
- **留空或未配置**：系统自动降级为本地规则模式（BM25 检索 + 合规层 + 确定性一餐生成），零配置即可跑，功能完整。
- 密钥纪律：真实密钥只经环境变量注入，**绝不写入代码或提交进版本库**；仓库仅保留 `.env.example` 模板。LLM 调用前有成本闸门保护（预算 / 缓存 / 限速 / 记账），不会因接真模型而失控。

## 四、它能为你做什么

1. **场景入口与一键方案**：首屏展示顾问人设欢迎语与四张场景卡（减脂塑形 / 增肌强化 / 控糖调理 / 今日食谱），点击即调 `/api/quick` 渲染真实方案卡；已有历史会话时自动恢复对话，欢迎语不重复。
2. **数值精确问答（防幻觉）**：问「鸡胸肉多少千卡」「鸡蛋多少蛋白质」等，返回权威速查表的精确值并标注来源（如 165 千卡/100g）；表中未收录的食材诚实告知，绝不臆测。
3. **三套方案推荐**：减脂（轻盈减脂方案）、增肌（力量增肌方案）、控糖（稳糖调理方案），返回热量区间、代表食材、推荐理由与来源。
4. **快捷操作**：顶部一键获取减脂 / 增肌 / 控糖方案或今日食谱。
5. **多轮对话与历史面板**：同一会话内上下文会被记忆，历史消息落库、刷新不丢；前端历史面板可查看并切换历史会话。
6. **过敏追问与记忆**：首次声明过敏/禁忌（如「我对海鲜过敏」）时，以真人顾问口吻追问细分类型（只问一次），并把禁忌持久化进会话画像——之后每一轮都记得、自动排除；消息隐含人群目标（如「血糖偏高」「想减脂」）会自动更新目标画像（减脂 / 增肌 / 调理）。
7. **一餐生成**：直接说「今晚减脂餐」「给我做晚餐」「今天吃什么」→ 得到**完整一餐**：主蛋白 + 主食碳水 + 蔬菜 + 好脂肪（含克数）、总热量、蛋白/碳水/脂肪三条、2-3 步做法、同族替换建议（蛋白/碳水各 2-3 个）；热量与营养素全部来自营养速查表真实值 × 份量（工具计算），表外食材（如橄榄油）标注「约计」不编造；无目标时先追问「想减脂、增肌还是控糖？」。
8. **一餐卡可视化**：一餐以卡片呈现——标题、食材清单（分类标签 + 克数 + 热量）、**总热量大数字**、营养素三条、做法步骤、替换建议、来源小字，卡片质感与整体 UI 一致。
9. **采购清单**：一餐卡内直接展示「采购清单」——由这餐的食材与克数一键派生，去菜场/超市照着买即可，不用自己再换算。
10. **饮食台账记录与回查**：说「早餐吃了两个鸡蛋和一杯牛奶」→ 记入饮食台账并按速查表估算热量；问「我最近吃了什么」→ 回查最近记录，形成「记住你吃了什么」闭环。
11. **情感陪伴**：说「一个人吃饭好孤单」「没胃口」「加班好累」等 → 先共情再轻建议，本地模式下建议食材同样来自速查表（零编造数值）。
12. **语音朗读（可选）**：每条助手回答右侧有小喇叭按钮，点击即用拟真人神经语音（微软 edge-tts，零 Key、零成本）朗读本条回答。edge-tts 为可选组件（见 `requirements-optional.txt`），**需联网调用微软语音服务**；未安装或网络不可用时朗读按钮不可用，文字回答不受影响。
13. **时间感知**：按当前时段（早/午/晚/夜宵）自动调整问候语与建议焦点——早上提醒高蛋白早餐、中午提醒 211 餐盘、晚上建议清淡少油；接入大模型时时段信息一并注入，回答更贴合当下。
14. **成长记忆（健康状态）**：基于饮食台账记住你的坚持与近况——首屏展示「连续坚持 N 天 / 今日已记 N 餐 / 近 7 天共记录 N 餐」，欢迎语结合坚持天数主动问候；接入大模型时，昨日概况与今日记录注入上下文，回答「结合你的情况」。
15. **点单决策（站在餐厅前的 30 秒）**：说「我在麦当劳准备点餐」「肯德基」「便利店」「吉野家」「兰州拉面」「中餐外卖」「火锅」等场景，系统按你的目标（减脂 / 增肌 / 调理）直接给出可执行点单建议（选什么 + 为什么 + 怎么改），如「麦香鸡去酱 + 玉米杯 + 无糖零度可乐」；点单建议为行为决策，只给定性指引（去酱 / 去皮 / 高蛋白 / 少油），不引用素材外的精确千卡/克数，具体以餐厅实际出品为准；已声明禁忌自动过滤，全部过滤则回退常规问答。
16. **为什么适合你（推荐解释）**：推荐方案卡内新增「为什么适合你」说明——基于你的目标（减脂 / 增肌 / 调理）解释方案的热量与蛋白定位、食材组合如何匹配你的阶段需求，不引入素材外数值。
17. **成本闸门**：LLM 模式下的预算、回复缓存、会话限速与成本记账，保证接入真实模型后费用可控、可观测。
18. **用药拒答与免责**：涉及疾病/症状/用药的问题强制附加医疗免责；含用药咨询一律拒答、只给膳食参考（判定优先级高于一餐、点单决策等其它意图）。
19. **禁忌排除**：对话中声明过敏/禁忌后，回答正文、推荐食材、一餐生成与点单建议均自动剔除对应禁忌食材，并明示排除清单。
20. **用户档案（"它记得我"）**：顶部点击头像打开档案抽屉——「我是谁」展示昵称 / 使用天数 / 当前目标（可点"切换目标"复用目标选择弹层）；「它记得我」汇总过敏与不耐受、慢病管理、已帮你排除的食材（chip 展示）、近 7 天记录与最近台账；「下一步建议」给出当前最该做的事（如"今天还差晚餐没记"），点击即可执行；支持**禁忌编辑**——按系统已知类别勾选（后端白名单校验，未知 id 安全过滤），保存后立即生效并影响后续所有回答。
21. **领域路由（两种模式）**：系统先判断这是「膳食顾问需求」还是「闲聊/非膳食」——营养、食材、热量、方案、禁忌类问题走知识库检索回答；打招呼（你好/早上好）、问身份、聊生活等自然回应，绝不硬套膳食内容（如"大龙虾吃什么"这类动物习性问题不会答成营养建议）。
22. **同义词查询扩展**：支持口语与别名问法——"鸡脯肉多少千卡"自动归一为"鸡胸肉"命中权威表、"减重/减肥"等同"减脂"、"西红柿"等同"番茄"；共 20 组食材 + 7 组概念同义词，评委口语问法不再因措辞差异漏判。
23. **疾病画像引导语**：当会话已声明慢病（高血压/糖尿病/痛风等），回答自动带"结合您的控盐/控糖/低嘌呤需求"的差异化引导，且跨轮延续——即使下一句没再提病名，小优也记得按你的情况回答。

## 五、能力边界与合规约定（红线）

1. **C 库隔离**：营养问答绝不混入平台价格、会员、企业方案等素材 C 内容；仅在明确问到平台服务时才检索 C 库（含"升级专业版/专业版怎么买/怎么开通"等平台问法）。
2. **医疗免责**：凡涉及疾病、症状、用药的问题，系统强制附加「本建议仅供参考，不构成医疗建议，请咨询专业医师或注册营养师」（含"三高/糖高"等口语变体；用户明确否认患病时不误加）。
3. **用药拒答**：含用药咨询（如「吃什么药」「布洛芬」「司美格鲁肽」「GLP-1 针」「降糖针」）一律不提供用药建议，且优先级高于一餐/检索等其它意图。
4. **数值防幻觉**：数值（热量/蛋白/碳水/克数）必须来自知识库权威表（速查表 × 份量），禁止模型推理编造；仅按精确食材名命中权威表（"鸡"这类泛指词不会误答成"鸡胸肉"），表外食材诚实告知"暂未收录"；一餐、台账估算、陪伴建议中的数值同一纪律。
5. **禁忌排除**：对话中声明过敏/禁忌（含"我不能吃虾/不吃海产品/对花生不耐受"等否定式说法）后，回答正文、推荐食材、一餐生成与点单建议均自动剔除对应禁忌食材（含"白煮蛋/加个蛋"等复合菜名）。
6. **零真实密钥**：代码与仓库不含任何真实 API Key，密钥仅经环境变量注入。

## 六、常见问题

- **为什么有的回答是检索原文、有的更口语？** 未配置密钥时为本地规则模式，回答逐字来自素材并标注来源；配置 `DEEPSEEK_API_KEY` 后升级为模型在检索结果上的自然语言组织，两者均不编造数值与医疗结论。
- **一餐的热量怎么来的？** 每个食材的热量/营养素取自营养速查表真实值，按份量（克/100）计算后求和；速查表未收录的食材（如橄榄油）不编造精确值，标注「约计」并说明。
- **点单建议为什么没有具体热量数字？** 点单决策是「站在餐厅/外卖前 30 秒」的行为建议，只告诉你选什么、怎么改（去酱 / 去皮 / 少油），避免给出未经权威核实的精确数字；具体以餐厅实际出品为准。
- **我怎么知道它记得我的过敏？** 首次声明过敏会收到追问与「已记录」确认；之后任意一轮，回复正文、推荐、一餐与点单建议都会自动剔除禁忌食材，并在尾部列出排除清单。也可以点顶部头像打开「用户档案」抽屉查看全部记忆，随时勾选管理禁忌。
- **小优怎么知道我得了什么病、目标是什么？** 你说出"我有高血压/糖尿病/痛风"或选择目标后，系统会把你的画像记进会话档案——之后回答带"结合您的控盐/控糖/低嘌呤需求"引导，跨轮延续；档案里的疾病信息只用于引导与免责延续，绝不绕过免责与用药拒答。
- **点小喇叭提示「暂不可用」？** 语音朗读为可选组件，依赖 edge-tts（需联网调用微软语音服务，零 Key、零成本）；未安装或网络不可用时优雅降级提示，不影响文字回答。
- **数据存哪里？** 本地默认 SQLite（WAL 模式），容器版存于命名卷；会话、历史与饮食台账本地持久化，不上云。
- **端口为什么是 8137？** 本地一键与容器部署均将演示口统一为 8137，避免与常用服务冲突。
