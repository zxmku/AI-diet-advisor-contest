# AI 辅助标注 · HealthPick 智能膳食顾问

> 本文件对应赛题「技术约束 · AI 辅助标注」要求（原题第 74 行）：
> **"选手需在文档中明确标注哪些模块由 AI 辅助生成、哪些由人工优化，并说明优化理由。未标注或虚假标注一经发现，取消参赛资格。"**
>
> 同时回应「禁止白标」（原题第 73 行）：本项目体现我们自身的设计、配置与逻辑能力，非任何商业产品的直接白标。

## 一、我们的团队模式（人机协同）

本项目采用 **「有人设计 · 有人组织 · AI 开发 · 人机协同」** 的研发模式：

| 角色 | 谁来做 | 在项目中体现 |
|---|---|---|
| **有人设计** | 架构 / 产品 / 交付负责人 | 系统架构、合规护栏设计、数据 schema、红线策略、Prompt 硬规则 |
| **有人组织** | 交付负责人 | 团队分工、任务拆解、QA 审核节奏、提交包清洗与交付物把关 |
| **AI 开发** | AI 辅助编程工具 | 代码骨架、样板结构、常规函数、文档初稿的生成 |
| **人机协同** | AI + 人闭环 | 每个模块走「AI 生成初稿 → 人工优化加固 → 回归固化」循环 |

> 一句话总结：**AI 负责"写得多、写得快"，人负责"设计边界、守住红线、组织交付"。** 这正是赛题第 71 行允许的 AI 辅助编程形态，也证明我们有真实的设计与逻辑，而非白标。

## 二、AI 辅助标识（标识方案 / 图例）

为让评审一眼看清每件交付物的来源，本项目统一使用以下四类标识：

| 标识 | 含义 | 适用对象 |
|---|---|---|
| **【AI生成】** | 由 AI 辅助编程工具首次产出的可运行代码 / 结构 / 文案，人工仅拼接微调 | 脚手架、样板、常规函数、文档草稿 |
| **【人工设计】** | 由人定义的安全 / 合规 / 数据 / 架构等**不可由模型随意改写**的边界 | 合规护栏、数值引擎、隔离闸门、Prompt 硬规则 |
| **【人工组织】** | 由人负责的流程、质量与交付动作 | 任务拆解、QA 审核、测试固化、打包清洗 |
| **【人机协同】** | AI 生成初稿、人工优化加固的迭代产物 | 绝大多数业务模块 |

> 标识应用在：① 本文档逐模块标注；② 源码关键文件头注释；③ 其余交付文档的对应说明。

## 三、逐模块 AI 辅助标注

| 模块 / 层 | 标识 | AI 辅助生成（AI开发） | 人工优化（设计 / 组织） | 优化理由 |
|---|---|---|---|---|
| **知识工程**（素材 A/B/C → 结构化 JSON） | 人机协同 | 三域（营养基础 / 个性化方案 / 平台服务）结构化 JSON 草稿、章节与表格初稿 | 逐块核对数值与来源；C 库单独建「平台意图触发词」门禁并物理隔离索引；9 类禁忌映射按合规合同整理 | 知识库是零编造根基，数值与禁忌须人工背书（红线①⑤） |
| **后端接口**（FastAPI 6 端点 + 统一响应） | 人机协同 | 路由骨架、Pydantic 模型、统一响应初稿 | 统一所有端点走同一出口保证契约一致；补安全头 / 按会话限流 / 全局异常兜底；空·超长输入按指定提示语 | 接口契约是评审对照物，须稳定可审计 |
| **合规护栏**（拒药 / 免责 / 禁忌剔除） | 人工设计 | 关键词表、路由分支骨架初稿 | 安全边界（用药拒答、疾病免责、禁忌全链路剔除）由人确定性设计，固定话术不可被模型改写；用药词表按通用名+命名族扩充、刻意不收录营养补剂防误报 | 安全边界交模型自由发挥会漂移 / 被绕过，属评委红线，必须人守（红线②③） |
| **LLM 合成层**（DeepSeek 动态生成 + 闲聊） | 人机协同 | `synthesize()` 骨架、基于检索块 grounding 调用模型生成 | 系统提示三处硬约束（禁用药建议 / 禁编造数值 / 未覆盖须明说）；用药·疾病类上游硬拦截不进 LLM；无命中允许自然闲聊 | 接真模型后仍须"绝不裸奔、零编造"（红线③⑤） |
| **数值引擎**（`nutrition_lookup` 速查表 × 规则） | 人工设计 | 函数骨架与格式化 | 数值改为确定性计算而非模型生成；一餐生成器数值纪律写死（每食材热量等一律取速查表真实值 × 份量）；表外食材标"约计"不计入 | 红线⑤要求数值只引素材原文，模型推算会编造 |
| **前端交互**（聊天界面 / 场景卡 / 一餐卡 / 历史 / 档案） | 人机协同 | 界面骨架、卡片 HTML/CSS、场景卡 / 历史面板初稿 | 首屏"有 / 无历史"互斥逻辑；真实取数非假数据；检测才渲染防 XSS；过敏追问真人顾问口吻 | 首屏是评审第一印象，须真实取数（红线⑤） |
| **测试与质量**（pytest 回归套件） | 人工组织 | 按红线清单生成 API / 单元用例初稿 | 强化环境隔离（临时库 / 置空 Key / 不污染生产库）；补盲区断言（正文不含禁忌食材）；全部固化回归 | 测试即交付证据，须可重复全绿（红线⑥） |
| **部署与打包**（Docker / 一键启动 / 提交包） | 人工组织 | Dockerfile、docker-compose、打包脚本初稿 | 修复缺前端 COPY、compose 读 `.env` 留空即降级、端口对齐 8137、SQLite 重定向命名卷持久化；提交包经清洗扫描 0 命中 | 容器版是验收路径之一，须"打开即见 UI、配 Key 即升级、重启不丢数据" |
| **产品化迭代**（场景卡 / 过敏记忆 / 一餐 / 台账 / 陪伴 / 成长记忆 / 点单决策 / 档案） | 人机协同 | 各功能初版实现与文案 | 数值纪律、禁忌统一、C 库单一事实源、会话归属校验、否定式 / 负面表述识别等人机协同加固 | 产品体验与红线守卫需协同打磨（红线②③⑤） |

## 四、诚实声明

1. **如实反映开发过程**：AI 负责提速样板与常规逻辑，人负责所有"安全 / 合规 / 不编造"的确定性边界。不存在将 AI 生成内容伪称为纯人工，也不存在将人工成果记为纯 AI。
2. **非白标**：本项目使用 AI 辅助编程工具生成代码（符合赛题第 71 行），但系统架构、合规护栏、数值引擎、素材隔离闸门等核心设计与逻辑均由团队人工完成，体现自身开发 / 设计 / 配置能力，非任何商业产品的白标。
3. **可核实**：各项人工优化均有对应测试回归固化，评审可对照源码与 `tests/` 目录核实。

> 标注口径说明：**AI 辅助生成** = 大模型基于需求描述首次产出的可运行代码 / 结构 / 文案，人工仅拼接微调；**人工优化 + 理由** = 人类针对正确性、合规、安全、成本、评审可验证性所做的必要改动，并写明动机。
