# AI 辅助标注 · HealthPick 智能膳食顾问

> 本文档逐项标注本项目在「AI 辅助编程」模式下，各模块哪些内容由 AI 辅助生成、哪些由人工优化，以及优化的原因，供评审对照源码与测试记录核实。术语沿用项目任务卡编号（MOD-01…M18），与架构说明一致。P1–P5 产品化迭代（场景卡 / 过敏记忆 / 一餐 / 一餐卡 / 台账 / 陪伴）与整夜迭代（TTS 热插拔 / 时间感知 / 成长记忆 / 点单决策 / 历史趋势 / 推荐解释）及 QA 两轮审核修复的标注见文末追加行。

## 一、标注口径

- **AI 辅助生成**：指由大模型基于需求描述首次产出的可运行代码/结构/文案，人工仅做拼接与微调。
- **人工优化 + 理由**：指人类工程师针对正确性、合规、安全、成本、评审可验证性所做的必要改动，并写明动机。

## 二、逐模块标注

| 模块 / 交付物 | AI 辅助生成 | 人工优化 + 理由 |
|---|---|---|
| **MOD-01 知识库工程**（素材 A 营养基础 16 块 / B 三套方案 14 块 / C 平台服务 15 块 + 禁忌映射 + 同义词） | 按「营养基础 / 个性化方案 / 平台服务」三域生成结构化 JSON 草稿，给出章节与表格初稿。 | 人工逐块核对数值与来源（如鸡胸肉 165 千卡/100g 与权威表逐字一致）；为 C 库单独建「平台意图触发词」门禁并物理隔离索引；`taboo_map.json` 9 类禁忌（海鲜/痛风/肾病/麸质/孕期/哺乳/控压/坚果/乳糖）由人工按合规合同整理，含触发词与排除食材清单。理由：知识库是零编造的根基，数值与禁忌必须人工背书。 |
| **MOD-03 API 网关基座**（FastAPI 6 端点 + 统一响应 + 安全头/CORS/限流/异常兜底） | AI 生成 FastAPI 路由骨架、Pydantic 模型与统一响应 `{data, sources, disclaimer?, meta}` 初稿。 | 人工统一所有端点走 `make_response` 出口，保证契约一致；补安全响应头、按会话/用户级限流（非纯 IP）、全局异常兜底文案「服务繁忙，请稍后重试」；空/超长输入按蓝图 8.4 指定提示语处理。理由：接口契约是评审对照物，必须稳定且可审计。 |
| **M13 LLM 合成层**（DeepSeek 动态生成 + 闲聊自然化） | AI 生成 `synthesize()` 骨架：基于检索块拼接 grounding、调用 DeepSeek 生成自然语言回答。 | 人工加三处硬约束：① 系统提示硬性禁止用药建议、禁止编造营养数值，资料未覆盖必须明说；② 用药/疾病类问题由合规层在上游硬拦截，绝不进入 LLM；③ 无检索命中时允许 LLM 自然回应「你好」等闲聊，失败再降级规则话术。理由：接入真模型后仍必须「绝不裸奔、零编造」。 |
| **M17 成本闸门**（预算 / 缓存 / 限速 / 记账） | AI 生成三层保护初稿：预算检查、回复缓存、会话限速。 | 人工补记账账本（当日 tokens/calls/cost 落盘 + 原子写）与 `/health` 成本状态观测；**修复 DEFECT-1**：缓存仅覆盖无上下文的单轮请求，带 history 的多轮请求跳过缓存读写，杜绝跨会话上下文串扰；限速按会话维度（非全局），防止单用户耗尽配额。理由：接真模型后无上限烧 token 是评审红线，闸门必须可观测、可回归（见 tests/test_cost_gate.py）。 |
| **历史会话面板**（前端历史面板 + `/api/history` 会话聚合） | AI 生成前端历史面板骨架与 `/api/history` 查询初稿（按 user_id 拉取消息）。 | 人工实现按会话聚合返回（`sessions` 数组含 message_count / first_message，按最近活跃排序），前端同源静态挂载、免 CORS；多轮上下文取最近 2 条用户消息参与检索、疾病意图跨轮延续免责。理由：会话列表是评审演示入口，聚合逻辑需真实读库且顺序稳定。 |
| **用药检测词表扩充** | AI 生成基础用药关键词（药/用药/剂量等）。 | 人工按「通用名 + 命名族尾缀」扩充（布洛芬/对乙酰氨基酚/头孢/沙星/霉素/地平/洛尔/替丁/格列汀/列净等），并刻意**不收录**维生素、钙片、蛋白粉等营养补剂，宁精勿滥防误报；对「地平线」类易误报词只收完整药名。理由：评审会用常见药诱导，词表必须覆盖广且不误伤膳食建议。 |
| **R3 禁忌正文剔除** | AI 原有实现仅在被拒答/推荐时于末尾追加「已按禁忌排除」提示语。 | 人工修复 QA 实测缺陷：`/api/chat` 回复正文若命中含禁忌食材的知识块仍会原样展示（如海鲜过敏用户仍看到「鳕鱼/虾仁」）。现于追加提示语**之前**先将正文中禁忌食材替换为「（已按禁忌剔除）」（长名优先），`_plan_from_goal` 推荐理由同步剔除，LLM 模式经 `excluded_foods` 参数注入系统提示强约束；配套红线用例（tests/test_redlines.py R3 组）。理由：红线②「禁忌必排除」必须对正文生效，而非仅提示。 |
| **Docker 部署修复**（frontend COPY / .env 注入 / 端口与数据卷） | AI 生成 Dockerfile 与 docker-compose 初稿（后端 + 知识库 + 8000 端口）。 | 人工修复三处：① Dockerfile 补 `COPY frontend/`——后端静态挂载缺前端则容器只能出 API 出不了 UI；② compose 用 `${DEEPSEEK_API_KEY:-}` 读取 `deploy/.env` 注入，留空即纯规则降级，零配置可跑；③ 端口映射 `8137:8000` 对齐演示口，SQLite 数据重定向到命名卷 `/app/data` 持久化，避免空命名卷覆盖代码目录。理由：容器版是评审验收路径之一，必须「打开即见 UI、配 Key 即升级、重启不丢数据」。 |
| **红线自动化测试**（pytest 回归套件 R1-R8） | AI 按红线清单生成 API 级与单元级用例初稿。 | 人工强化环境隔离（`conftest.py`：DATABASE_URL 指向临时库、DEEPSEEK_API_KEY 置空、backend 入 sys.path 后再 import，绝不污染线上 healthpick.db）；R3 用例补「正文（提示前）不含禁忌食材」断言，堵住原盲区；M17 用例 mock `_post_json` 不触网。理由：测试即交付证据，必须可重复、全绿、不污染生产数据。 |
| **P1 首屏人格与场景入口卡片**（欢迎语 + 四张场景卡 + /api/quick 联动） | AI 生成首屏欢迎语文案与场景卡 HTML/CSS 骨架，点击卡片调 `/api/quick`。 | 人工改造成「无历史展示欢迎语+场景卡、有历史恢复对话不重复欢迎语」的互斥逻辑；场景卡成功后淡出收起、失败保留可重试；`renderRec` 统一渲染真实推荐卡。理由：首屏是评审第一印象，必须真实取数而非假数据。 |
| **P2 过敏追问与目标记忆**（allergies/goal_tag 画像持久化 + 只问一次追问） | AI 生成「首次声明过敏 → 追加追问文案」与人群目标关键词初稿。 | 人工将追问改为**真人顾问口吻**（按禁忌 id 细分，如海鲜问虾/蟹/贝/鱼，只问一次），并把过敏/目标写回 `sessions` 跨轮生效；追问原文精确食材名（花生/腰果等）绝不进 R3 剔除循环防乱码；「给我/帮我」纯请求语义不覆盖已有目标画像（DEFECT-B）。理由：「记得我」必须真实落库且不因轮次丢失。 |
| **P3 一餐确定性生成器**（`_build_meal`，从问题到一餐） | AI 生成一餐结构模板（主蛋白/主食碳水/蔬菜/好脂肪 + 做法 + 替换）。 | 人工把**数值纪律写死进生成器**：每个食材热量/蛋白/碳水/脂肪一律 `nutrition_lookup.lookup` 取速查表真实值 × 份量（克/100）计算；表外食材（橄榄油）kcal=None 标注「约计」不计入总热量；禁忌食材在槽位与同族替换中全链路剔除；做法步骤取自 B 方案检索块/速查表「推荐做法」列并带来源；无目标先追问目标。修复 QA 两处优先级空隙：数值问答（`晚餐鸡胸肉多少千卡`→165）与用药拒答（`吃布洛芬后晚餐吃什么好`→拒答）均优先于一餐。理由：一餐是产品灵魂，数值必须可核对、绝不编造。 |
| **P4 一餐卡可视化**（前端 data.meal 渲染） | AI 生成一餐卡渲染骨架（标题/食材/热量/做法/替换/来源）。 | 人工沿用既有 CSS 变量与卡片质感，检测 `data.meal` 才渲染、未命中保持原 `renderRec`/`renderBot` 行为；`textContent` 渲染防 XSS；quick/推荐兼容 meal/plan 双路径。理由：契约式渲染不破坏既有功能，评审打开即见完整一餐。 |
| **P5a 饮食台账记录/回查**（diet_logs 表 + 速查表估算） | AI 生成 DietLog 落库、记录/查询意图初稿与「约 X 千卡」估算。 | 人工把热量估算限定为速查表真实值 × 份量（消息带克数按用户份量、否则 100g 常见份量），表外食材不显示数字；查询/记录互斥判定（问句/求方案语义「什么/推荐/给我做」绝不当作记录）；内容存原文、估算仅展示不落库，避免把估算当台账事实。理由：台账是「记得你吃了什么」的闭环，数值同样零编造。 |
| **P5b 情感陪伴**（一人食陪聊，先共情再轻建议） | AI 生成陪伴回复模板与触发词初稿。 | 人工改为「先共情再轻建议」，本地模板的建议食材复用 P3 一餐生成器（速查表保证、零编造数值）；LLM 模式经系统提示第 6 条约束，失败降级本地模板；meta.model 按 LLM 合成/本地规则双路径正确标注。理由：陪伴要像真人顾问，且任何路径都不裸奔、不编数值。 |
| **整夜迭代·TTS 语音输出热插拔**（tts_service + /api/tts + 前端 🔊 朗读按钮） | AI 生成 edge-tts 文本转语音骨架（拟真人神经语音，零 Key 零成本）与前端朗读按钮初稿。 | 人工改为**热插拔适配器**：edge-tts 未安装或合成失败一律 503 优雅降级、前端 toast 提示且不阻断文字回答；朗读前清洗 markdown 标记与「（已按禁忌剔除）」等提示性文案，让语音念起来自然；依赖写入 requirements.txt 随安装就绪。理由：语音是加分项，绝不能因缺组件拖垮主链路（降级不崩）。 |
| **整夜迭代·时间感知**（time_context + LLM 系统提示注入 + 前端时段问候） | AI 生成早/午/晚/夜宵四时段问候语与建议焦点文案初稿。 | 人工将时段上下文（period/greeting/focus）注入 LLM 系统提示，前端首屏按本地时刻切换问候语；纯函数、零依赖、无状态。理由：时间感知让回答「像当下的顾问」，但必须不引入外部依赖、不触碰业务核心。 |
| **整夜迭代·成长记忆**（health_state + /api/state + state_context 注入） | AI 生成今日/昨日总结、连续坚持（streak）与 AI 欢迎语初稿。 | 人工限定一切统计来源为 DietLog **真实落库**（UTC+8 自然日去重），异常一律降级返回空/0；`/api/state` 供首屏展示「连续坚持 N 天/今日已记/近 7 天」，LLM `state_context` 在检索回答/闲聊/陪伴**三处调用**注入（昨天+今天+坚持）。理由：成长记忆必须真实可核对，绝不凭对话猜用户坚持天数。 |
| **整夜迭代·点单决策**（decision_tool + chat 决策分支 + 数值纪律） | AI 生成 7 场景（麦当劳/肯德基/便利店/吉野家/兰州拉面/中餐外卖/火锅）× 3 目标（减脂/增肌/调理）点单模板初稿。 | 人工定**数值纪律**：点单建议是行为决策，只给定性指引（去酱/去皮/高蛋白/少油），绝不引用素材外精确千卡/克数，以「具体以餐厅实际出品为准」兜底；禁忌全链路过滤、全部过滤回退常规问答；`data.decision` 可选契约不破坏既有响应。理由：行为建议一旦出现未经权威核实的精确数字，就成了新的幻觉源，必须「只定性、不引数」。 |
| **QA 两轮审核修复**（决策数值守卫 / 误触发排除 / 用药硬拦截） | AI 初版决策分支仅按场景词触发。 | 人工修复三处：① **数值守卫**——决策分支加 `is_num_query` 前置门槛，「便利店鸡胸肉多少千卡」必须返回速查表精确值 165，绝不被点单建议劫持（MEDIUM）；② **误触发排除**——「聊聊/还没到/配送/多少钱/吐槽/怎么还不」等闲聊、抱怨、纯数值问不当作点单场景（LOW）；③ **用药硬拦截**——决策分支加 `is_med_query` 硬拦截，「吃布洛芬后怎么点餐」先拒答用药并带免责，绝不经决策分支绕过红线②（R2）。理由：新增分支必须过旧红线，评审诱导测试稳定合规。 |
| **整夜迭代·历史趋势**（近 7 天 week_trend + LLM 上下文 + 前端首屏） | AI 生成近 7 天逐日餐数/餐次聚合初稿。 | 人工改为按本地自然日（UTC+8）升序输出 7 天趋势（空日补 0），并入 `state_context` 供 LLM 感知，前端首屏展示「近 7 天共记录 N 餐」。理由：趋势必须稳定排序、缺日补零，避免「看起来断更」误导坚持判断。 |
| **整夜迭代·推荐解释**（_plan_from_goal 结构化 why + renderRec「为什么适合你」） | AI 初版推荐仅有 reason（素材 B 检索块首句）。 | 人工新增结构化 `why` 字段：基于目标（减脂/增肌/调理）与素材 B 方案字段（热量区间/食材组合）生成「为什么适合你」，不引入素材外数值；前端 renderRec 在 reason 后以独立区块展示，禁忌剔除同步生效。理由：推荐要「看得懂为什么」，且解释同样守数值纪律。 |
