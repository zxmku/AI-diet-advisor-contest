# 架构说明 · AI 智能膳食顾问（HealthPick）

> 本文档说明系统整体架构、分层职责与技术选型，供评审理解实现方式。全文不含内部工程黑话，仅描述可对外展示的工程事实。

## 一、总体分层（五层）

1. **交互层（前端）**：单文件移动端聊天界面（原生 HTML/JS，零构建、零前端依赖），同源静态挂载于后端，免 CORS、打开即跑。提供输入框、快捷按钮、示例气泡、来源标注、模型状态徽章、**历史会话面板**、**首屏场景入口卡片**（P1）与**一餐卡**（P4：总热量大数字 / 营养素三条 / 食材清单 / 做法 / 替换 / 来源 / **🛒 采购清单**）；助手回答带 **🔊 朗读按钮**（TTS 语音输出）；首屏按本地时刻切换时段问候，并展示**成长记忆状态条**（连续坚持 N 天 / 今日已记 N 餐 / 近 7 天共记录 N 餐）；推荐卡带 **💡 为什么适合你** 解释区；顶部 **👤 用户档案抽屉**（P0 记忆模块）三段展示「我是谁 / 它记得我 / 下一步建议」并支持禁忌勾选编辑。
2. **服务层（API 网关）**：FastAPI 提供 **8 个 REST 端点**（对话 / 推荐 / 快捷 / 历史 / 用户 / 会话 / 健康状态 `/api/state` / 语音 `/api/tts`），统一响应格式 `{data, sources, disclaimer?, meta}`，含安全响应头、CORS、限流与全局异常兜底。对话端点内部按**意图优先级**派发：**用药硬拦截 → 数值精确问答 → 一餐生成 → 点单决策 → 检索/LLM → 闲聊（非膳食）**；其中「膳食 vs 闲聊」由**领域路由门控**（`is_dietary_domain`）判定，非膳食问题绝不硬套知识库。
3. **智能层（检索 + 合成 + 确定性工具 + 合规 + 管道适配器）**：BM25 + jieba 轻量检索（RAG 检索域），查询先经 **synonyms 同义词扩展**（20 组食材 + 7 组概念别名归一，如 鸡脯肉→鸡胸肉 / 减重→减脂）；可选 DeepSeek LLM 合成层在检索结果之上生成自然语言回答；**确定性一餐生成器**（P3 `_build_meal`）按目标人群从素材 B 方案取食材、经营养速查表真实值 × 份量计算热量与营养素，输出结构化一餐（items/shopping_list/total_kcal/macros/method/swaps/sources），禁忌全链路剔除；**饮食台账**（P5a）落库并按速查表估算热量；**情感陪伴**（P5b）先共情再轻建议；**用户档案聚合**（P0 `_build_user_profile`）只读聚合身份/偏好/行为/下一步建议，零写库、零合规豁免；**管道适配器（热插拔）**：时间感知（time_context 时段问候/建议焦点）、语音输出（tts_service 拟真人神经语音，缺失/失败优雅 503）、健康状态引擎（health_state 连续坚持/今日/昨日/近 7 天）、点单决策工具（decision_tool 7 场景 × 3 目标，数值纪律只定性不引素材外数值）、成长记忆注入（state_context 注入 LLM 三处调用）与推荐解释（_plan_from_goal 结构化 why）；M17 成本闸门在真实 API 调用前做预算 / 缓存 / 限速 / 记账四重保护（缓存键含用户维度，杜绝跨用户串扰）；合规层以规则硬逻辑实现免责、拒药（词表 + 白名单豁免）、禁忌排除（13 类禁忌映射）、密钥管理与输入校验——不依赖模型自觉，稳定可审。
4. **数据层**：SQLite（WAL 模式）存储用户 / 会话 / 消息 / 方案缓存 / 饮食台账**五表**（含 DietLog）；知识库为本地 JSON（素材 A 营养基础 16 块、素材 B 三套方案 14 块、素材 C 平台服务 15 块 + 禁忌映射 + 同义词），零外部数据库、零向量库；**运行时数据**（成本账本 / 回复缓存）默认 `backend/data`，可用 `HEALTHPICK_DATA_DIR` 环境变量覆盖（测试隔离与部署自定义）。
5. **部署层**：双轨部署——本地一键脚本（Windows bat，端口 8137）与 Docker Compose 容器（`8137:8000`，命名卷持久化）；知识库与前端随镜像打包；密钥仅经环境变量注入。

## 二、关键技术决策

- **双层知识库，C 库物理隔离**：素材 A+B 为营养与方案核心域，合并建同域索引；素材 C（平台价格/会员/企业方案）为辅助隔离域，**仅当用户显式命中平台意图时才检索**，从代码层杜绝价格信息污染营养回答。平台意图词表为**单一事实源**（retrieval 定义、main 复用，含 会员/价格/多少钱/收费/费用/套餐/订阅/平台/开通/升级/付费/企业/SaaS/API/案例/白皮书/定价/专业版/标准版/免费版/购买/续费），杜绝词表漂移导致平台问法检索不到 C 库。
- **意图优先级（防劫持）**：对话端点按固定顺序判定——**用药硬拦截 → 数值精确问答 → 一餐生成 → 点单决策 → 检索/LLM → 闲聊（非膳食）**；P5 饮食管理（记录/查询）与情感陪伴互斥优先。用药硬拦截与数值精确作为**前置门槛**同时约束一餐与决策分支：由此保证「晚餐鸡胸肉多少千卡」返回速查表精确值（不被一餐/决策劫持）、「吃布洛芬后晚餐吃什么好」先拒答用药并带免责（不进一餐/决策）、「在麦当劳准备点餐，鸡胸肉多少千卡」返回速查表精确值（不被点单建议劫持）。
- **领域路由门控（两种模式）**：`is_dietary_domain` 以「营养概念 + 目标方案 + 健康疾病 + 食材名」为领域信号（刻意不含泛化动词"吃/喝/什么/怎么"），判定膳食需求走 RAG、非膳食（打招呼/问身份/闲聊/动物习性等）走闲聊自然回应——「大龙虾吃什么」不会硬套知识块，避免 BM25 低相关检索污染回答。
- **同义词接线（查询扩展 + 别名归一）**：检索前把用户口语/别名问法归一为标准词（`synonyms.json` 20 组食材 + 7 组概念，如 鸡脯肉→鸡胸肉、西红柿→番茄、减重→减脂），再进入速查表命中与知识检索，评委口语问法不再因措辞差异漏判。
- **用户档案聚合（P0 记忆模块）**：`/api/state` 新增只读 `profile` 段（identity 昵称/使用天数、preferences 目标/过敏/排除食材/疾病标签、behavior 坚持/今日/近 7 天/最近台账/今日未记录餐次、next_step 下一步建议）+ `taboo_options`（前端禁忌编辑渲染），全部复用现有 users/sessions/diet_logs/health_state/taboo_map，零新表；**守卫 1** 禁忌 id 白名单——`/api/session` 入口与写库双过滤未知 id（安全失败、不误清既有禁忌）；**守卫 2** 档案疾病类禁忌只驱动免责延续与引导语（`_session_profile_has_disease` + `_profile_guide` 标签反查），拒药/免责硬判定仍以消息关键词为准；**守卫 3** profile 纯展示聚合，自由文本不进 LLM。
- **确定性一餐生成（从问题到一餐）**：命中一餐意图（晚餐/午餐/早餐/今晚/给我做/今天吃什么/晚上吃什么等）时，`_build_meal` 按目标人群（消息内目标词 → 会话画像 → 追问目标）从素材 B 方案/食谱取食材，构成「主蛋白 150g + 主食碳水 100g + 蔬菜 200g + 好脂肪 10g」四槽位；每个食材的热量/蛋白/碳水/脂肪一律 `nutrition_lookup.lookup` 取速查表真实值 × 份量（克/100）计算，表外食材标注「约计」不编造；禁忌食材在槽位与同族替换中全链路剔除；做法步骤取自 B 方案检索块与速查表「推荐做法」列并带来源标注；**采购清单由一餐 items 派生**（shopping_list 字段），前端一键展示。前端检测到 `data.meal` 即渲染一餐卡，未命中保持原契约。
- **画像记忆与追问（P2）**：对话中声明的过敏/禁忌与隐含人群目标持久化进 `sessions.allergies / goal_tag`，跨轮生效（记得我）；首次声明过敏以顾问口吻追问细分类型（只问一次），确认排除提示与免责保留在回复尾部；一餐无目标时先追问目标。
- **管道适配器热插拔（整夜迭代）**：时间感知（time_context）、语音输出（tts_service）、健康状态（health_state）、点单决策（decision_tool）均为**独立管道节点**，不触碰业务核心（检索/禁忌/免责）；缺失、失败一律优雅降级（如 TTS 503 → 前端 toast；state 异常返回空/0），绝不打断主流程。
- **成长记忆注入（state_context）**：health_state 基于 DietLog 真实落库（UTC+8 自然日去重）计算连续坚持天数 / 今日总结 / 昨日概况 / 近 7 天趋势，组装成文本注入 LLM 系统提示（**三处调用**：检索回答、闲聊、陪伴），让模型「结合昨天与今天」作答；`/api/state` 向首屏提供 streak / today_summary / week_trend / greeting。
- **推荐解释（M5 Explain My Plan）**：`_plan_from_goal` 在素材 B 方案字段（热量区间 / 食材组合）基础上生成结构化 `why`（「为什么适合你」），不引入素材外数值；前端 renderRec 在 reason 后以独立区块展示，禁忌剔除同步生效。
- **检索 grounding + LLM 合成 + 成本闸门**：未配置密钥时走本地规则（BM25 检索原文 + 合规层，零编造、带来源）；配置密钥后升级为 DeepSeek 动态合成，回答仍严格基于检索块；所有 LLM 调用先过 M17 成本闸门（当日预算超限即降级、同消息 TTL 内缓存命中、单会话 60 秒限速、调用成功记账），防止接真模型后无上限烧 token。
- **统一响应契约**：全部端点返回 `{data, sources, disclaimer?, meta}`，`meta.model` 标识当前模型（`local-rules` 或 `deepseek-chat`）、`meta.degraded` 标识是否降级，前端据此展示模型徽章；一餐以 `data.meal` 可选字段附加（含 shopping_list），点单决策以 `data.decision` 可选字段附加（scenario/goal/items/note），均不影响既有渲染。
- **合规硬逻辑**：免责（疾病/症状/用药词命中即注入标准文案；含三高/糖高/血压有点高等口语变体）、拒答用药（词表含通用名与命名族尾缀，如布洛芬/头孢/沙星/列净/GLP-1/降糖针，且不误伤维生素/蛋白粉等补剂；裸「药」命中时对「山药/药膳/药食同源」白名单豁免）、禁忌排除（13 类禁忌映射，正文与推荐理由双剔除；支持"我不能吃X/不吃X/X不耐受/碰都不能碰"否定式识别与多字食材整词匹配，鱼油/蛋白粉等补剂负向守卫不误伤）、输入校验（空/超长按指定提示语兜底，入口剥离 C0 控制符）、限流（会话/用户级）——均为确定性规则，评审诱导测试稳定合规。
- **记忆只读用户陈述**：会话历史扫描（疾病延续、画像引导）仅统计 `role=user` 的消息，模型/检索输出永不当用户事实——普通用户不会被素材块中的疾病词误判成病人。
- **会话归属校验**：会话画像（目标/禁忌）读写均校验 `session.user_id` 归属，杜绝跨用户串号与档案泄露。
- **负面表述识别**：疾病判定前剥离否定结构（"没有/没得/正常/不是/并无"+疾病词），用户否认患病时不误贴疾病画像、不误加控糖引导。
- **降级不崩**：LLM 不可用、知识库缺失、DB 异常、成本闸门故障、TTS 缺失/失败均只降级不崩溃；任何失败路径都有明确兜底文案，绝不裸奔。

## 三、模块映射

后端按任务卡推进：MOD-01 知识库工程、MOD-02 检索路由、MOD-03 API 网关基座、MOD-04 会话与历史持久化、MOD-05 推荐引擎、MOD-08/10/11 合规层（免责/禁忌/拒药）、MOD-14 数据层（WAL）、MOD-15/16 部署；M13 LLM 合成层（含闲聊自然化）、M17 成本闸门、M5 推荐解释、M18 欢迎语。产品化迭代 P1 首屏人格与场景卡、P2 过敏追问与目标记忆、P3 一餐确定性生成器、P4 一餐卡可视化、P5a 饮食台账（`diet_logs` 表）、P5b 情感陪伴。整夜迭代新增 **6 个管道适配器模块**：time_context（时段感知）、tts_service（语音输出，`/api/tts`）、health_state（成长记忆，`/api/state`）、decision_tool（点单决策，`data.decision` 契约）、state_context 注入（LLM 三处调用）、why 解释（`_plan_from_goal` + renderRec）。今日迭代新增：**领域路由门控**（`is_dietary_domain` 膳食 vs 闲聊）、**synonyms 同义词接线**（查询扩展 + 别名归一）、**M11 疾病画像引导语**（双模板 + 跨轮延续）、**逻辑层审计修复**（V01-V11，覆盖 P5 用药拦截/鱼大豆鸡蛋过敏族/GLP-1 拒药/坚果不误报/疾病免责词表/缓存用户隔离/药字白名单/餐次触发词/GI 门控/引号保护标记加固）、**用户档案 P0 记忆模块**（`_build_user_profile` 聚合 + 前端 👤 档案抽屉 + 守卫 1/2/3）。终审加固迭代（二审深度审核 + 波次修复）：**数值精确匹配**（速查表按精确食材名命中，单字/整菜/泛指词不再误答，量词前置问法回退整句提取）、**点单决策禁忌统一**（决策过滤与一餐生成器共用 `_is_food_excluded`，白煮蛋/加个蛋等复合菜名正确排除）、**C库词表单一事实源**（升级专业版/专业版怎么买 等平台问法正确召回）、**会话归属校验**、**否定式禁忌识别**、**负面表述剥离**、**记忆只扫用户陈述**、**针剂词表补全**。前端为单文件 UI（含历史面板、场景卡、一餐卡、采购清单、朗读按钮、成长记忆状态条、为什么适合你、用户档案抽屉）。配套交付：`tests/` 红线自动化回归套件（R1-R8 及 P2/P3/P5 与迭代适配器/健康状态/决策守卫/用户档案/终审加固用例，**168 项全绿**）、`30_测试记录/` 测试记录、`20_交付文档/` 使用说明与 AI 辅助标注。各模块经统一数据契约协作，源码位于项目仓库。
