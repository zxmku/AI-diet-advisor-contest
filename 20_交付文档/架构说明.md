# 架构说明 · AI 智能膳食顾问（HealthPick）

> 本文档说明系统整体架构、分层职责与技术选型，供评审理解实现方式。全文不含内部工程黑话，仅描述可对外展示的工程事实。

## 一、总体分层（五层）

1. **交互层（前端）**：单文件移动端聊天界面（原生 HTML/JS，零构建、零前端依赖），同源静态挂载于后端，免 CORS、打开即跑。提供输入框、快捷按钮、示例气泡、来源标注、模型状态徽章、**历史会话面板**、**首屏场景入口卡片**（P1）与**一餐卡**（P4：总热量大数字 / 营养素三条 / 食材清单 / 做法 / 替换 / 来源）。
2. **服务层（API 网关）**：FastAPI 提供 6 个 REST 端点（对话 / 推荐 / 快捷 / 历史 / 用户 / 会话），统一响应格式 `{data, sources, disclaimer?, meta}`，含安全响应头、CORS、限流与全局异常兜底。对话端点内部按**意图优先级**派发：用药硬拦截 → 数值精确问答 → 一餐生成 → 检索/LLM/其他（并互斥优先 P5 饮食管理与陪伴）。
3. **智能层（检索 + 合成 + 确定性工具 + 合规）**：BM25 + jieba 轻量检索（RAG 检索域）；可选 DeepSeek LLM 合成层在检索结果之上生成自然语言回答；**确定性一餐生成器**（P3 `_build_meal`）按目标人群从素材 B 方案取食材、经营养速查表真实值 × 份量计算热量与营养素，输出结构化一餐（items/total_kcal/macros/method/swaps/sources），禁忌全链路剔除；**饮食台账**（P5a）落库并按速查表估算热量；**情感陪伴**（P5b）先共情再轻建议；M17 成本闸门在真实 API 调用前做预算 / 缓存 / 限速 / 记账四重保护；合规层以规则硬逻辑实现免责、拒药、禁忌排除、密钥管理与输入校验——不依赖模型自觉，稳定可审。
4. **数据层**：SQLite（WAL 模式）存储用户 / 会话 / 消息 / 方案缓存 / 饮食台账**五表**；知识库为本地 JSON（素材 A 营养基础 16 块、素材 B 三套方案 14 块、素材 C 平台服务 15 块 + 禁忌映射 + 同义词），零外部数据库、零向量库。
5. **部署层**：双轨部署——本地一键脚本（Windows bat，端口 8137）与 Docker Compose 容器（`8137:8000`，命名卷持久化）；知识库与前端随镜像打包；密钥仅经环境变量注入。

## 二、关键技术决策

- **双层知识库，C 库物理隔离**：素材 A+B 为营养与方案核心域，合并建同域索引；素材 C（平台价格/会员/企业方案）为辅助隔离域，**仅当用户显式命中平台意图时才检索**，从代码层杜绝价格信息污染营养回答。
- **意图优先级（防劫持）**：对话端点按固定顺序判定——**用药硬拦截 → 数值精确问答 → 一餐生成 → 检索/LLM/其他**；P5 饮食管理（记录/查询）与情感陪伴互斥优先。由此保证：「晚餐鸡胸肉多少千卡」返回速查表精确值（不被一餐劫持）、「吃布洛芬后晚餐吃什么好」先拒答用药并带免责（不进一餐）。
- **确定性一餐生成（从问题到一餐）**：命中一餐意图（晚餐/午餐/早餐/今晚/给我做/今天吃什么等）时，`_build_meal` 按目标人群（消息内目标词 → 会话画像 → 追问目标）从素材 B 方案/食谱取食材，构成「主蛋白 150g + 主食碳水 100g + 蔬菜 200g + 好脂肪 10g」四槽位；每个食材的热量/蛋白/碳水/脂肪一律 `nutrition_lookup.lookup` 取速查表真实值 × 份量（克/100）计算，表外食材标注「约计」不编造；禁忌食材在槽位与同族替换中全链路剔除；做法步骤取自 B 方案检索块与速查表「推荐做法」列并带来源标注。前端检测到 `data.meal` 即渲染一餐卡，未命中保持原契约。
- **画像记忆与追问（P2）**：对话中声明的过敏/禁忌与隐含人群目标持久化进 `sessions.allergies / goal_tag`，跨轮生效（记得我）；首次声明过敏以顾问口吻追问细分类型（只问一次），确认排除提示与免责保留在回复尾部；一餐无目标时先追问目标。
- **检索 grounding + LLM 合成 + 成本闸门**：未配置密钥时走本地规则（BM25 检索原文 + 合规层，零编造、带来源）；配置密钥后升级为 DeepSeek 动态合成，回答仍严格基于检索块；所有 LLM 调用先过 M17 成本闸门（当日预算超限即降级、同消息 TTL 内缓存命中、单会话 60 秒限速、调用成功记账），防止接真模型后无上限烧 token。
- **统一响应契约**：全部端点返回 `{data, sources, disclaimer?, meta}`，`meta.model` 标识当前模型（`local-rules` 或 `deepseek-chat`）、`meta.degraded` 标识是否降级，前端据此展示模型徽章；一餐以 `data.meal` 可选字段附加，不影响既有渲染。
- **合规硬逻辑**：免责（疾病/症状/用药词命中即注入标准文案）、拒答用药（词表含通用名与命名族尾缀，如布洛芬/头孢/沙星/列净，且不误伤维生素/蛋白粉等补剂）、禁忌排除（9 类禁忌映射，正文与推荐理由双剔除）、输入校验（空/超长按指定提示语兜底）、限流（会话/用户级）——均为确定性规则，评审诱导测试稳定合规。
- **降级不崩**：LLM 不可用、知识库缺失、DB 异常、成本闸门故障均只降级不崩溃；任何失败路径都有明确兜底文案，绝不裸奔。

## 三、模块映射

后端按任务卡推进：MOD-01 知识库工程、MOD-02 检索路由、MOD-03 API 网关基座、MOD-04 会话与历史持久化、MOD-05 推荐引擎、MOD-08/10/11 合规层（免责/禁忌/拒药）、MOD-14 数据层（WAL）、MOD-15/16 部署；M13 LLM 合成层（含闲聊自然化）、M17 成本闸门。产品化迭代 P1 首屏人格与场景卡、P2 过敏追问与目标记忆、P3 一餐确定性生成器、P4 一餐卡可视化、P5a 饮食台账（`diet_logs` 表）、P5b 情感陪伴。前端为单文件 UI（含历史面板、场景卡、一餐卡）。配套交付：`tests/` 红线自动化回归套件（R1-R8 及 P2/P3/P5 迭代用例，27 项）、`30_测试记录/` 测试记录、`20_交付文档/` 使用说明与 AI 辅助标注。各模块经统一数据契约协作，源码位于项目仓库。
